Shared, mobile, VPN, or reassigned IPs can create false matches, so automatic exact-match bans are optional.

Start here

Four steps to your first check.

  1. Download Beta 11 and choose Extract All.

    In Windows File Explorer, right-click the downloaded ZIP and select Extract All. Open the extracted folder before running anything.

  2. Run Install StreamShield.cmd.

    Double-click Install StreamShield.cmd in that folder and let installation finish. Launch StreamShield using the shortcut the installer creates.

  3. Select Connect KICK.

    Review the permissions on KICK’s official authorization page and approve the connection. Return to StreamShield after authorization completes.

  4. Run the Pre-Stream Check.

    Read the result for each check and resolve any connection or monitoring problem. Keep StreamShield running during your stream; live-only checks need a real live stream and real events.

Already using an earlier beta? Close it before running the Beta 11 installer, then reconnect KICK and rerun the check.

Windows publisher notice: this beta is not yet commercially code signed. If Windows blocks installation, leave system security protections enabled and contact the person who supplied your beta access.

While you stream

A practical routine.

  • Open Compact Control. Keep the small window beside your stream tools and use the full dashboard when you need deeper history.
  • Review the reason for an alert. Raids, promotions, and sudden audience growth can be legitimate. Use the Event Board and a viewer’s Case File before escalating moderation.
  • Choose your automation settings. Automatic user timeouts are a separate opt-in. Mark known regulars as trusted and review the protections you enable.
  • Select suspicious chatters for verification. In Recent KICK Chat, use Require Verification beside the specific account. StreamShield temporarily restricts that account, creates a one-time link for the moderator to send, and tracks the result in the verification queue.
  • Correct mistakes using the right control. Recovery Center can reverse supported recent actions. Manage network blocks with UN-IP BAN and KICK account bans with the account unban control.
  • Review the report after an incident. Keep useful evidence for channel moderation or a KICK support request. A report’s evidence seal helps detect file changes; it does not prove the underlying accusation.

Optional network protection

Exact matches need context.

Only people who use StreamShield’s verification flow can provide a verified connection record. KICK does not supply viewer IPs to StreamShield.

Public IP addresses can be shared or reassigned. With the separate exact-match auto-ban setting enabled, a newly verified account matching a blocked IP can be banned. Review possible false positives.

Targeted verification also uses a random first-party browser token. A token match is a moderator review signal by default; it is not a permanent device identity.

Troubleshooting

If a check does not pass.

  • KICK is disconnected: reopen StreamShield, select Connect KICK, and complete authorization again.
  • Monitoring is degraded: read the specific failed check and Event Board message. Confirm your internet connection, then rerun the check.
  • Live monitoring is pending: keep the app open during your next normal stream. Offline channels may have no viewer count or recent live events.
  • A viewer cannot verify: after clicking Require Verification, StreamShield copies the newest one-time link to the moderator’s clipboard. Paste that link to the selected viewer manually. The viewer must continue with the exact KICK account selected by the request; another account is rejected. If the request expired or was released, create a new request.
  • A moderation mistake happened: use Recovery Center or the specific account/network control, then confirm the updated status.
Privacy by scope

Know what is stored.

Streamer OAuth tokens are encrypted on the streamer’s PC. The cloud broker processes authorization and refresh data transiently. Buffered public chat text expires after 15 minutes and event rows after 24 hours. Optional viewer verification adds a keyed one-way network identifier, not a stored full IP address; targeted verification can also add a hashed random browser token, with a cookie lifetime of up to 90 days.
