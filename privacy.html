Privacy & Data Controls

StreamShield uses channel activity to support defensive moderation. Additional viewer connection data is collected only through StreamShield’s optional verification flow after the viewer chooses to continue.

Channel data and OAuth

The desktop app stores the connected KICK channel identity, encrypted OAuth tokens, aggregate activity baselines, incident summaries, and moderation action records. Streamer OAuth tokens are encrypted locally on the streamer’s computer.

The cloud OAuth broker processes authorization codes and tokens only as needed to exchange or refresh credentials. It does not persist streamer OAuth tokens. A viewer who verifies signs in with KICK; StreamShield does not ask for the viewer’s password.

Short-lived event buffering

Signed KICK events are buffered so the desktop app can receive them reliably. Buffered public chat text expires after 15 minutes. Whole webhook event rows expire after 24 hours. Raw chat text is not written into long-term incident reports.

Optional network verification

Network Protection is off by default. When a viewer reads the verification notice, selects Continue with KICK, and completes authorization, the verification service can associate that KICK account with the connection’s public IP address. The exact verified IP is stored encrypted at rest, and a keyed one-way network signature supports exact matching.

Authorized channel moderation controls can display the verified IP, linked KICK account, verification times, and block history. This information supports the streamer’s defensive moderation and ban-evasion review. Opening KICK or watching a stream alone does not create a StreamShield verified IP record.

The site and verification service receive ordinary connection information when a browser requests a page. A page visit by itself does not authorize a KICK identity link or create a completed channel verification record.

Targeted verification and a browser token

When a moderator requests verification of a specific chatter, StreamShield also uses a random first-party browser token. Its cookie lasts for up to 90 days; the server stores a keyed one-way hash of the token for matching, rather than the raw token. Associated token observations are retained for up to 90 days.

This token is a resettable browser identifier. It is not a hardware identity or an invasive fingerprint. Clearing site data, changing browser profiles, or changing devices can reset it. StreamShield does not collect hardware serial numbers, canvas fingerprints, or similar device fingerprints.

Browser-token matches are moderator review signals by default. They do not, by themselves, establish that two accounts belong to the same person.

Limits of network matching

StreamShield does not obtain viewer IP addresses from KICK. It cannot identify a viewer’s connection if that viewer never uses StreamShield’s verification service.

Network Protection and exact-network automatic bans require streamer opt-in. Public IP addresses may be shared by several people or reassigned to someone else. A matching address is not proof of a shared identity. Streamers should review possible false positives and provide a way for viewers to contact the channel’s moderation team.

Controls and deletion

The app includes Disconnect KICK and Delete My StreamShield Data. The deletion control removes the local channel baseline, incident history, encrypted session and connected token state, and the channel’s short-lived cloud event buffer. Do not assume a local reset erases every saved verification or block record; review those separately with the channel’s moderation team.

UN-IP BAN removes a network block and cancels pending automatic enforcement for that IP. It does not automatically unban KICK accounts that have already been banned. Clearing a browser cookie does not erase an existing server record or account ban.

Viewers with a verification, access, or record-removal question should contact the streamer or moderation team that provided their verification link.

What is not collected

StreamShield does not collect KICK passwords, private messages, stream keys, hardware serial numbers, or invasive browser fingerprints. It does not request advertising, payout, or stream-key access for these protection features.

These public pages

The release and verification pages have no analytics scripts or advertising trackers. The verification consent page does not automatically start KICK authorization. Its form submits only after the viewer selects the continue button. The consent page sends only this site’s origin, without the verification link’s path or query, as referrer information. Result pages use a no-referrer policy. Both are served with no-store caching instructions.
