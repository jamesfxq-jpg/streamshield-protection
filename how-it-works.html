HOW STREAMSHIELD WORKS

A clear process from alert to action.

StreamShield connects your channel’s activity, your moderation choices, and your verification history. Here is what happens at each step.

01 · Connect and prepare

Your channel is the starting point.

The streamer runs the Windows app and connects through KICK’s authorization page. The approved permissions let StreamShield read supported channel events, send verification replies, and perform the moderation actions you choose.

Pre-Stream Check checks the connection, event subscriptions, cloud relay, and protection readiness. A pending live-event check becomes useful once a real channel event arrives. Keep the desktop app and internet connection running while using StreamShield.

02 · Follow channel activity

See why something was flagged.

StreamShield watches supported chat and follow events and polls official viewer data. Its dashboard groups the signals into an assessment with the triggering reasons, recent activity, and a timeline.

Automatic message handling

Enabled chat and link shields can delete qualifying spam through your authorized moderation connection. Automatic user timeouts are a separate opt-in.

Human moderation

From recent chat, choose Verify / Resend, timeout, Ban & Shield, unban, or a case file. The recommended network preset keeps possible matches for review.

03 · Verify a selected chatter

One request. A guided check. A private result.

  1. The moderator selects Verify / Resend.

    StreamShield creates a one-time request for that KICK account before applying a temporary chat restriction.

  2. The link is delivered in KICK chat.

    A neutral reply mentions the selected chatter and includes their account-bound verification link. A ready-made copy-and-paste fallback is available when automatic delivery fails. The reply is public chat, not a private message.

  3. The viewer reviews the notice and continues.

    The StreamShield page explains the privacy-protected network identifier and first-party browser token. The viewer chooses Continue with KICK and authorizes the requested account.

  4. StreamShield checks the retained history.

    A clean result can release the restriction created by this installation. A blocked-network or browser-token signal is shown to moderators for review. A newer permanent ban takes priority over an older verification request.

Need to resend? A still-pending request can reuse its original link and expiry, without a second timeout. Successful automatic resends for that active link are limited to one per minute.

04 · Handle possible repeat abuse

Ban & Shield connects the next decision to the previous one.

Ban & Shield permanently bans the selected KICK account and checks its retained verified network history. With Network Shield enabled, the signed ban-event backend marks the relevant history for later matching. Ordinary bans made in KICK use that existing event path too.

The private result tells your team whether the network history is blocked, still syncing, unavailable, or missing. Another account that later completes verification from the blocked network can be flagged as a possible repeat-abuse match.

A network match is a clue, not an identity verdict. Family members, shared connections, VPNs, and reassigned addresses can match. Review the account’s behavior and case history before deciding what to do. Advanced exact-network auto-ban is available separately.

05 · Recover and review

Keep the action and its reason together.

Case files bring recent chat, recorded moderation actions, verification outcomes, and masked network history into one view. Recovery Center helps reverse supported recent actions.

Unban changes the KICK account restriction. Remove Network Block changes the stored network block. Use the control that matches the mistake; one does not automatically reverse the other.

After the stream, review the summary and export a report. The integrity seal helps check whether a saved report has changed.

A simple setup for streamers and moderators.

The streamer runs the desktop app. Selected moderators can use the restricted web dashboard from their own device; their actions are executed through the streamer’s running app. Viewers only see the verification flow when asked to complete it.
