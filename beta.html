Safe beta testing

Start conservative.

  • Test on your own KICK channel and use only accounts whose owners agreed to the test.
  • For your first stream, leave automatic user timeouts and exact-network auto-ban off.
  • Never paste passwords, KICK tokens, stream keys, private messages, or exact viewer IP addresses into feedback.
  • An alert is a reason to review activity, not proof that a viewer caused an attack.
What we need most

Report what actually happens.

  • Installation or update failures.
  • KICK connection, event, viewer-count, or relay problems.
  • Controls that are confusing, missing, slow, or unreliable.
  • False positives, missed suspicious activity, or unsafe moderation behavior.
  • Crashes, frozen screens, lost settings, reconnect problems, or report problems.
Beta test checklist

Run these in order.

  1. Install and launch.

    Extract the ZIP, run Install StreamShield.cmd, and confirm the dashboard opens at localhost:8787.

  2. Connect KICK.

    Use the official KICK authorization screen. Confirm your correct channel appears in StreamShield.

  3. Run Pre-Stream Protection Check.

    Record anything shown as failed, degraded, or pending. Offline channels may legitimately be waiting for a real signed KICK event.

  4. Generate one ordinary real event.

    During an authorized test, have a consenting account chat or follow. Confirm StreamShield receives the event and updates health/status.

  5. Use Compact Control.

    Resize it, keep it beside your stream tools, and check that recent chat, protection status, case controls, and recovery controls remain usable.

  6. Test a controlled verification.

    Only with a consenting test account: open Recent KICK Chat, click Require Verification beside that chatter, copy the ready-to-paste @username verification message, send it directly to that tester, have them select Continue with KICK, and confirm the verification queue and temporary restriction update correctly.

  7. Test recovery carefully.

    Use only consenting accounts. Check timeout/unban or supported Undo actions one at a time. Confirm an independent permanent ban is not removed by an older verification unlock.

  8. Test selected moderator access.

    From Recent KICK Chat, invite one consenting test account with Invite Mod. Open the private invite on another browser/device, connect the exact invited KICK account, verify the remote Mod Dashboard and Compact Pop-Out load, run one harmless command, then revoke access from the streamer dashboard and confirm the remote session stops working.

  9. Check reporting.

    Generate or review the stream report, verify the evidence seal, and confirm the summary describes what StreamShield actually recorded.

  10. Check OBS branding.

    Add one included PNG as an OBS Image source. Confirm it looks sharp, resizes cleanly, and does not interfere with your normal scene layout.

Do not use ordinary viewers as test subjects for bans or verification. Moderation and verification tests should be limited to accounts that explicitly agreed to participate.

Moderator workflow

How to select a viewer for StreamShield Verification.

  1. Open Recent KICK Chat.

    Use the full StreamShield dashboard or Compact Control while the connected channel is receiving chat.

  2. Choose the account.

    Find the chatter you want to test and click Require Verification beside that user. StreamShield places a temporary chat restriction on that selected account.

  3. Paste the generated link to the selected viewer.

    When Require Verification succeeds, StreamShield copies a ready-to-paste @username message containing the one-time link to the moderator’s clipboard. StreamShield does not automatically DM the viewer through KICK. Paste it into KICK chat while mentioning the selected viewer, or send it through a private contact method you already use. The link is bound to the selected KICK account.

  4. The viewer continues with KICK.

    The tester opens the link, selects Continue with KICK, and authorizes the KICK account named by the request.

  5. Review the result.

    A clean result can release the StreamShield-owned temporary restriction. Network or browser-token matches should be reviewed, and exact blocked-network auto-ban should remain off during early beta testing unless the test specifically covers it.

Updating Beta 11

Keep your data.

  1. Close StreamShield.
  2. Download the newest beta ZIP from this site.
  3. Choose Extract All.
  4. Run the new Install StreamShield.cmd.
  5. Reopen StreamShield and rerun the Pre-Stream Protection Check.

The installer updates application files while retaining the existing application data directory. Still report any lost settings, reconnect problem, or unexpected reset.

Windows notice

Beta software can fail.

This beta is not yet commercially code signed, so Windows may show an unknown-publisher warning. Do not disable Windows security protections to install it. StreamShield can also miss activity, report false positives, lose connectivity, or make a moderation action you need to reverse.

KICK controls its own platform, enforcement, monetization, and Partner Program decisions. StreamShield is not a KICK service and cannot guarantee a platform outcome.

Beta feedback

Tell us what happened.

A successful test is useful feedback too. For bugs, include the exact steps that led to the problem. Do not submit credentials, stream keys, OAuth tokens, private messages, or exact viewer IP addresses.

Beta tester disclaimer

Important limits.

StreamShield Beta 11 is pre-release defensive software. Features can fail, change, or produce incorrect results. It does not guarantee detection or prevention of botting, ban evasion, fake engagement, harassment, or other abuse. Automated and network-based actions can produce false positives, especially with shared, mobile, VPN, or reassigned networks.

Use conservative settings, review alerts before escalating moderation, and keep the normal KICK moderation tools available. By testing, you are helping evaluate the product; you are not being asked to weaken your account security or expose confidential information.
